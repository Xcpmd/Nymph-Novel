## 依据 main.md 生成 Nymph Novel 项目

## 重置 AI 生成流程：事件驱动大纲机制

把原先「章节概括 + 分层摘要」的生成流程整体替换为「故事事件 + 大纲步骤」机制。

### 数据模型变化

- 新增 `story_events` 表，承载事件标题、事件内时间、大纲步骤 JSON、当前进度指针、状态与所属分支。
- `timeline_events` 保留作为跨分支时间轴索引，通过 `event_id` 与故事事件关联，不再从章节概括推导。
- 新增 `encyclopedia_queries` 与 `event_recall_requests` 两张表，分别记录大纲阶段提出的设定查询与往期事件调阅请求。
- `chapters` 表删除 `summary`、`summary_level`、`plot_impact`、`importance` 四列，新增 `event_id` 与 `step_index`。
- `novels` 新增 `cover_image` 与 `cover_fit`，`characters` 新增 `speech_hue` 与 `speech_color_mode`。
- 迁移以 user_version 顺序推进到 v4：v2 建事件相关表，v3 删概括列并扩展封面与发言色，v4 为章节补事件关联列。

### 生成流程

- 第一章生成时注入数据库全部内容，产出若干故事方向选项加一个自填选项。
- 用户选定方向后生成事件大纲，以 Markdown 输出，并用 `<step time="...">` 区块列出有序步骤。
- 写正文时把前一章全文与全部已完结事件大纲一并发给模型，模型用 `<step-status value="done|partial">` 标记写到哪一步。
- 事件全部步骤走完后自动置为完成，再次询问故事方向，进入下一个事件。
- 模型可通过 `<query>` 请求查询百科，通过 `<recall event="...">` 请求调阅往期事件章节，后者受偏好开关限制。
- 章末自动抽取新出现的人物、地名与名词，产出待入库的百科条目与角色条目。

### 角色发言标记

- 正文中角色发言统一写作 `<talk chara="角色名">发言内容</talk>`，不写双引号。
- 渲染时先转成私有区字符定界的行内代码，绕过 HTML 清洗白名单，再由自定义 code 组件还原为带双引号的对白。
- 色相存 HSL 数值，由 AI 添加角色时按黄金角序列分配，角色图鉴内可手动调整。
- 颜色明暗随主题切换，`--talk-hue` 驱动。

### 界面变化

- 小说 PATCH 路由原先没有透传 coverImage 与 coverFit，导致书架换封面会静默失效，已补上。
- `deleteNovelFiles` 直接抛错会让整个删除接口返回 500，而数据库记录其实已经删掉了。已改为捕获异常并记录告警，删除不再被目录清理失败拖累。

### 迁移设计上的教训

schema 里的注释写着「每一步都是幂等的 SQL 语句集合」，但 `ALTER TABLE ADD COLUMN` 本身并不幂等，重复执行会报重复列。真正保证幂等的是「版本号已应用就跳过」这一层。因此已发布的迁移版本不能再改内容，只能追加新版本。

## 二次修复设定保存失效，并全面移除中文路径

上一轮声称修好了设定保存，实际没修好。用户复现后重查，找到了真正的原因。

### 真正的原因：展开顺序覆盖

- 上一轮只改了 `NOVEL_TEXT_KEYS` 的键名，没发现更深的一层。
- `getNovelPreferences` 执行的是 `SELECT key, value FROM novel_settings WHERE novel_id = ?`，**没有排除文本键**。早期版本已经把 worldview、setting 以 JSON 字符串形式写进这张表，值是 `""`。于是返回的 `preferences` 对象里带着 `worldview: ''` 这些字段。
- 前端保存时的请求体是 `{ ...current.texts, ...current.preferences, rules }`，**preferences 展开在 texts 之后**，那些空串就把用户真正输入的内容覆盖掉了。
- 世界观与核心设定之所以看起来正常，是因为它们的键名一直没错，但同样是空串覆盖，所以实际也没存住。表现就是「写了一整篇，保存刷新全没了」。
- 磁盘上留下了五个 0 字节的 md 文件，这就是「文件里也是空的」的来源：文件被创建了，写入的却是被覆盖后的空串。

### 三层修复

1. **前端**：请求体改为 `{ ...current.preferences, rules, ...current.texts }`，文本字段放在最后。
2. **服务端**：`getNovelPreferences` 跳过文本键（`isNovelTextKey` 判断），同一个响应里不再出现两套可能冲突的文本值。
3. **兼容**：`isNovelTextKey` 同时识别驼峰与历史下划线写法，读写两侧都不漏。

### 中文路径全面拉丁化

- `paths.ts` 重构：目录名由 `卷-001/章-001/正文.md` 改为 `vol-001/ch-001/content.md`。
- 提供 `legacyVolumeDirName`、`legacyChapterRelPath`、`normalizeVolumeDirName`、`normalizeContentRelPath`、`isLegacyVolumeDir`、`isContentFileName` 一组兼容函数。
- 设定目录由 `设定与规则/世界观.md` 改为 `setup/worldview.md`，五项文件名分别是 worldview.md、setting.md、outline-overview.md、ending-plan.md、style-sample.md。

### 排查手法

多端口并存是这次的核心干扰。同一项目有六个服务同时监听 3100 到 3150，浏览器访问的那个很可能跑着旧代码。定位方式是逐个 `curl` 各端口的 `/api/novels` 与首页 title，确认它们指向同一份数据后，用 `PATCH` 各自回显来比对行为差异，再从磁盘文件的字节数确认「文件存在但为空」。以后遇到「改了代码但行为没变」，先确认访问的端口与访问的服务是不是当前这份代码。

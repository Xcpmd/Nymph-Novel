## 修复「显示生成完成但内容区为空」

现象：界面提示生成完成，正文区与右下角日志都是空的，但 token 已被消耗。

根因定位（三层叠加，逐层验证后确认）：

1. **上游推理模型把内容放在 `reasoning_content`**。
   `deepseek-flash` 的流式帧实测为
   `{"delta":{"content":null,"reasoning_content":"我们需要"}}`，
   `content` 全程为 `null`。`src/lib/ai/client.ts` 原先只读
   `parsed.choices[0].delta.content`，整条流被静默丢弃，`full` 为空。

2. **`usage` 与 `done` 仍然照常返回**，因此上层把「一个字都没有」
   记成 `done`。用户看到的是「生成完成 + 空白」。

3. **`finish_reason: "length"` 被完全忽略**。
   `params.maxTokens` 为 8192，实测尾帧
   `{"content":"","reasoning_content":null,"finish_reason":"length"}` 且
   `completion_tokens_details.reasoning_tokens = 64`，
   即额度全烧在思考上，正文一字未写。原先这种情况照常走完流程。

修复要点：

- `client.ts` 抽出纯函数 `parseStreamLine`，同时产出 `content` 与
  `reasoning` 两路增量，并带出 `finishReason` 与用量。
  新增 `reasoning` 流事件类型，思考过程与正文彻底分离。
- 正文为空而有推理内容时，`chatStream` 直接产出 `error`，
  不再让上层误判成功。
- `route.ts` 新增 `truncated` 事件，`finish_reason === 'length'` 时
  明确告知被截断；`usageJson` 一并记录 `finishReason`。
- 服务端在流结束时把 AI 返回的完整内容打印到控制台
  （含结束原因、是否出现推理增量、用量、正文字符数），
  排查时不必再靠猜。
- `useGeneration` 新增 `reasoning` / `truncated` 状态；
  结束时若正文为空则强制置为 `error` 并给出可操作提示。
  同时 `start` 改为返回 `{ text, error, truncated }`，
  供连续生成直接取用，避免读到旧的 React state。

验证证据：

- 修复前：`event: delta` 计数为 0，`done` 的 `length` 为 0。
- 修复后：13 个 delta + 11 个 reasoning，`done.length = 21`，
  正文拼接为「你好，很高兴见到你，今天想聊点什么故事呢？」。
- 截断分支：`maxTokens: 48` 时 48 个 reasoning、0 个 delta，
  服务端返回明确 error；日志记为 `failed` 而非 `done`。

回归测试：新增 `src/lib/ai/client.test.ts`，帧数据照抄真实响应，
覆盖正文增量、推理增量、首帧空 role、length 尾帧、`[DONE]`、
心跳行、非 JSON 行、无 usage 共 8 例。

## 计划性连续生成

需求：连续生成至指定章数，一章一章生成，发送时必须包含上一章正文。

实现（`WorkbenchClient.tsx`）：

- 新增「连续生成章数」输入与「按计划连续生成」按钮，上限 50 章。
- **逐章串行**推进，不能并发：后续章节依赖前面章节的正文与推进后的进度，
  并发发出时每一章拿到的「上一章正文」都指向同一章，内容会互相重叠。
- 每一轮新建一章 → 生成 → 落库 → 按 `parseStepStatus` 决定是否推进事件 →
  进入下一轮。服务端 `buildContext` 每次请求独立读库，
  因此刚落库的上一章正文能被 `findPreviousChapter` 取到。
- 连续生成时 `autoAdvanceEvent: false`，进度由外层统一推进，
  避免单次生成各自改动。
- 提供「停止」按钮，走 `planAbortRef` + `generation.pause()`。
